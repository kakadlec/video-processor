## 1. Configuration: the public endpoint

- [ ] 1.1 `internal/video/infrastructure/storage/config.go`: add `PublicEndpoint` and `PublicUseSSL` to `Config`, read from `VIDEO_MINIO_PUBLIC_ENDPOINT` and `VIDEO_MINIO_PUBLIC_USE_SSL`. Both optional; each defaults to its internal counterpart — `PublicEndpoint` to `Endpoint`, `PublicUseSSL` to the **resolved** `UseSSL`, not to `false`. Reuse the existing `boolFromEnv` so a present-but-unparseable value is an error rather than a silent `false`, exactly as `VIDEO_MINIO_USE_SSL` already behaves.
- [ ] 1.2 Comment why the pair exists, in one sentence a reader cannot guess: SigV4 signs `Host`, so a signed URL's host cannot be rewritten after issuance, and the internal endpoint is routinely a name only the server resolves (`docker-compose.yml` sets `minio:9000`). The public value is used to *construct* URLs and is never dialed by the server.
- [ ] 1.3 Do **not** add a region variable. Task 3.2 discovers it. If implementation makes that look inconvenient, re-read design.md decision 5 before reaching for an env var.

## 2. Domain: the port changes

- [ ] 2.1 `internal/video/domain/result_storage.go`: add the presigning operation to `ResultStorage`. Signature returns the URL, the instant it stops being accepted, and an error — the expiry comes back from the adapter because only the adapter can read it off the signature (task 3.1a). The filename to present to the browser is a parameter, not derived inside the adapter, so key derivation stays in one place.
- [ ] 2.2 Remove `Open` from the port and its doc comment. Its only caller is `handleDownload`, which stops streaming in task 4.1. Leaving a reader-returning method on the port invites a future caller back into the data path this change removes (design.md decision 2).
- [ ] 2.3 Add `ErrResultPresignFailed`, for the same reason `ErrResultStoreFailed` exists: the client's error text names the endpoint and bucket and must not reach a response body or a persisted reason.
- [ ] 2.4 On the presigning method's doc comment, state the bound as **request admission**: the storage service refuses a request that *arrives* after the expiry, a transfer already in flight runs to completion, and clock skew moves the effective instant either way. Do not write "the URL expires" or "access stops" (design.md decision 6a). This wording has leaked back into a comment once already in this phase, after the spec had been corrected.

## 3. Adapter and startup wiring

- [ ] 3.1 `internal/video/infrastructure/storage/result_storage.go`: implement presigning with `PresignedGetObject`, passing `response-content-disposition` in the request parameters so MinIO returns `Content-Disposition: attachment` naming the key. Verified against the pinned stack: the parameter is honored and is covered by the signature (altering it after issuance yields `403`). Wrap any error in `ErrResultPresignFailed`. Remove the `Open` implementation.
- [ ] 3.1a **Derive the returned expiry from the issued URL's own signed fields** — parse `X-Amz-Date` (layout `20060102T150405Z`) and add `X-Amz-Expires` seconds — never `time.Now().Add(ttl)`. Measured against the pinned stack: the signature's start instant is stamped at whole-second precision, so an independently computed value overstated the real window by 561 ms in one issuance; and a requested `5m0.5s` signed as exactly `300` seconds, silently dropping the remainder. An `expires_at` that overstates the credential is worse than none — a client that trusts it retries after the service has stopped accepting. Comment the parse; the two-line arithmetic is otherwise indistinguishable from an over-complicated `time.Now()`.
- [ ] 3.2 The adapter needs a *presign-only* client, distinct from the one it uses for `Put`/`Stat`. Construct it from `PublicEndpoint`/`PublicUseSSL` **and an explicit `Region`**. The region requirement is not stylistic: on a client with no configured region, `PresignedGetObject` first issues `GetBucketLocation` against its own endpoint — measured failing with `dial tcp: lookup … no such host` against an unreachable public host, and succeeding in ~150 µs with the region set. Record that in a comment; it is invisible from the call site.
- [ ] 3.3 `cmd/api/video.go`'s `setupVideo`: after `EnsureBucket`, call `GetBucketLocation` on the **internal** client and pass the result into the presign-only client's construction. This joins the existing fail-closed startup sequence — a failure is fatal, like `Ping` and `EnsureBucket` before it.
- [ ] 3.4 Comment, at the construction site, that the presign-only client is deliberately never pinged and never used for a bucket or object operation, because it points at a host the server generally cannot reach. `add-minio-infrastructure` already specifies that construction performs no connectivity check, so this is a permitted use — but "a client we never talk to" is otherwise indistinguishable from a wiring bug.
- [ ] 3.5 Define the TTL as an unexported five-minute constant beside the handler, with the reasoning attached: issuance happens on click, not on listing, so the interval that must be survived is the sub-second gap between the JSON response and the browser's navigation. No environment variable (design.md decision 6).

## 4. The download endpoint becomes an issuer

- [ ] 4.1 `cmd/api/video.go`'s `handleDownload`: keep the five entitlement conditions, in the same order, evaluated against the same undecorated repository. Replace the `Open` + `DataFromReader` tail with `Stat` → presign → `c.JSON(200, …)` carrying the URL and the expiry instant.
- [ ] 4.2 The `Stat` is not optional and is not a leftover. Signing is local and succeeds for a key holding no object, so without it a deleted object would surface as a `404` from MinIO — different origin, XML body — instead of this endpoint's byte-identical `404` (design.md decision 7). Map its not-found *and* its error cases to the same `respondArtifactNotFound`.
- [ ] 4.3 Route a presign failure to the same `respondArtifactNotFound`, logging the **key** and the underlying error. The branch is in practice unreachable (the TTL is a constant inside the library's accepted `[1s, 7d]` range and the key is already validated), but it must not be the one path that leaks an endpoint name into a body.
- [ ] 4.4 **Never log, echo, or persist the issued URL.** It is a credential; the key is not. Every log line on this path names the key, matching what the handler already does (design.md decision 9).
- [ ] 4.4a Set `Cache-Control: no-store` on **every** response this handler produces, success and rejection alike. On the `200` it stops a private or user-agent cache from retaining a working credential past the request that asked for it — an authenticated `200` is otherwise ordinarily cacheable, which would defeat the short lifetime the whole design rests on. Setting it on the rejections too is what keeps them byte-identical to each other, which "Every Download Rejection Is Byte-Identical" requires down to headers.
- [ ] 4.5 Update the handler's doc comment: it authorizes and issues, it does not serve. State that issuance is the *complete* authorization decision, because nothing re-checks ownership when the URL is redeemed.
- [ ] 4.6 Leave `handleStatus` alone. `download_url` stays `/download/<key>` — the URL you call to *start* a download, which is still accurate. Minting URLs into the listing was considered and rejected (design.md decision 6): it starts every TTL at listing time and puts one credential per completed job into a single body.
- [ ] 4.7 Leave `ResultStorageKey`'s flat shape alone, and do not "clean up" the comment justifying it. The key is still `GET /download/:filename`'s single path segment, so the no-`/` constraint is still load-bearing; re-keying would orphan every stored object (design.md decision 3).

## 7. Tests

- [ ] 7.1 `config_test.go`: the public endpoint and TLS defaults (each following its internal counterpart), each honored when set, the independent-TLS case (internal plaintext, public TLS), and a malformed `VIDEO_MINIO_PUBLIC_USE_SSL` rejected rather than defaulted.
- [ ] 7.2 **The load-bearing adapter test**: store an object of known content, issue a URL, request it with **no `Authorization` header**, and compare the received bytes to what was stored. Structural assertions on the query string pass happily against a URL that `403`s, so they cannot stand alone (design.md, Risks).
- [ ] 7.3 Alongside it: `Content-Disposition` is returned and names the key; a disposition altered after issuance is refused; an expired URL is refused. For the expiry case, sign with the library's 1-second minimum rather than sleeping out a five-minute constant.
- [ ] 7.4 A presigning client configured against a public endpoint that does not resolve still issues a URL, and that URL's host is the configured public endpoint. This is the case region discovery exists for; without it, a regression that drops the region turns into a startup-time network failure nobody's test catches.
- [ ] 7.5 Do **not** write a test asserting that an in-flight transfer is cut off at expiry — it is not, and the scenario in the spec asserts the opposite. If a large-object test is added for that scenario, it must assert completion.
- [ ] 7.5a Assert the reported expiry equals the instant encoded in the URL's signature, not merely that it is roughly `now + 5m`. A tolerance-based assertion passes against the naive computation this task exists to forbid, so it must compare against the parsed `X-Amz-Date` + `X-Amz-Expires` (task 3.1a).
- [ ] 7.6 `cmd/api/video_test.go`: the download tests move from asserting zip bytes to asserting a `200` with a URL and an expiry, then following that URL and comparing bytes. Keep every existing byte-identical-`404` case and add the two new ones — object deleted from the bucket, and presign failure — asserting identical status, body, and headers.
- [ ] 7.6a `Cache-Control: no-store` on the issuance response **and** on a rejection. The byte-identical-`404` assertions compare headers, so a header set on only one path would surface there — but assert it directly rather than relying on that to catch it.
- [ ] 7.7 A test that a rejected request mints nothing: exercising the not-entitled path must not produce a usable URL by any route.
- [ ] 7.8 `rate-limiting`'s download scenario: update the assertion from "no object retrieved from storage" to "no object stated and no URL issued".
- [ ] 7.9 Delete or rewrite whatever `Open`'s removal orphans in `result_storage_test.go`, including the "opening a missing artifact fails before any reader is returned" coverage. The existence guarantee it protected moves to the handler's `Stat`; make sure a test covers it there before deleting it here.
