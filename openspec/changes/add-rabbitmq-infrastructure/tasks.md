## 2. Package: `internal/platform/rabbitmq`

- [ ] 2.1 `config.go`: `Config` with a single `URL` field, `LoadConfigFromEnv` reading `RABBITMQ_URL`, and an exported `ErrURLRequired` returned when the variable is unset or empty. One field, not a decomposed host/port/user/vhost set — the URI is AMQP's own addressing form and carries the TLS scheme, the credentials, and the vhost that a bare address cannot express. Mirror `internal/platform/redis/config.go`'s shape and error style.
- [ ] 2.2 `client.go`: `Open(cfg Config) (*amqp091.Connection, error)` calling `amqp091.Dial`. Unlike `redis.Open` and `storage.Open` this genuinely connects (design.md decision 2) — record that in a doc comment with the reason, so a later consistency pass does not "fix" it into a deferred-connect shim. The wrapped error must not echo `cfg.URL`: an AMQP URI carries the password in its userinfo component, and this error reaches logs.
- [ ] 2.3 `client.go`: `Ping(conn *amqp091.Connection) error` that opens a channel and closes it. Do **not** use `conn.IsClosed()` — it reports only what this process has already observed, which is stale for exactly the unreachable-broker case a health check exists to catch (design.md decision 3, and the same trap `minio-infrastructure` documents for `minio-go`'s cached `IsOnline`). Note in a comment why the cheap predicate was rejected.
- [ ] 2.4 `client.go`: `Close(conn *amqp091.Connection) error`. Unlike the MinIO adapter, which has no teardown because `*minio.Client` exposes none, an AMQP connection owns a socket and must be released.
- [ ] 2.5 `topology.go`: an exported `Topology` descriptor with fields for the five names (exchange, routing key, job queue, dead-letter exchange, dead-letter queue) and the four bound values (job TTL, job max length, dead TTL, dead max length), plus `DefaultTopology()` returning `video.jobs`, `video_job.queued`, `video.jobs.queued.v1`, `video.jobs.dlx`, `video.jobs.dead`, 1 h, 10 000, 24 h, 10 000. The routing key matches the outbox `event_type` string `add-videojob-source-key-and-outbox-relay` will persist. The `.v1` suffix is deliberate and not speculative generality: the cutover consumes from a separately named queue rather than purging this one, so the successor is a convention rather than an ad-hoc rename (design.md decision 4). The two overflow policies and the dead-letter queue's lack of its own DLX are **not** fields — they are the invariants that make the topology bounded, and a caller able to vary them could declare an unbounded chain through this API (design.md decision 6).
- [ ] 2.6 `topology.go`: `DeclareTopology(conn *amqp091.Connection, topo Topology) error` opening **its own** channel and closing it before returning, so a failed declaration cannot leave a caller's long-lived channel closed — AMQP gives no way to reopen the same channel. Declaration order is fixed and load-bearing: dead-letter exchange, dead-letter queue, and its binding **first**, then the job exchange, the job queue, and its binding. RabbitMQ does not validate that a queue's `x-dead-letter-exchange` exists at declare time and silently drops dead-lettered messages when it does not, so declaring the sink first makes a partial failure leave an incomplete topology rather than a complete-looking lossy one (design.md decision 6).
- [ ] 2.7 `topology.go`: declare the job queue durable with the descriptor's TTL and max length (1 h / 10 000 by default), `x-overflow: reject-publish-dlx`, and `x-dead-letter-exchange: video.jobs.dlx`. `reject-publish-dlx` over the default `drop-head`: a refused publish lets the relay leave its outbox row unstamped and retry, while a dropped head is a job that vanishes with no record it was queued — and `reject-publish-dlx` dead-letters what it refuses, so the refusal is inspectable (design.md decision 5).
- [ ] 2.8 `topology.go`: declare the dead-letter queue durable with the descriptor's dead-letter TTL and max length (24 h / 10 000 by default), `x-overflow: drop-head`, and **no** `x-dead-letter-exchange`. This is what terminates the chain — a bound on the job queue alone relocates growth into an unbounded sink rather than capping it, and during the window `add-videojob-source-key-and-outbox-relay` opens, that sink is where every message ends up.

## 3. Tests: `internal/platform/rabbitmq`

- [ ] 3.1 Shared helper: read `RABBITMQ_TEST_URL` and `t.Skip` with a clear message naming the variable when unset — matching `internal/platform/redis/client_test.go:21` and `internal/video/infrastructure/storage/client_test.go:30` exactly, not `cmd/api`'s `TestMain` fail-hard posture. Nothing in the running application opens an AMQP connection after this change, so there is no coverage a skip would silently hide.
- [ ] 3.2 Second helper: build a `Topology` whose five names are derived from the test name plus a random suffix, starting from `DefaultTopology()` so the bound values stay the production ones unless a test deliberately overrides them, and register `t.Cleanup` deleting every exchange and queue it declared so cleanup runs on failure too. Tests call the real exported `DeclareTopology` with this descriptor; they must never declare `DefaultTopology()`'s own names, since a test-sized `max-length` left behind under a production name collides with the real declaration later, as `PRECONDITION_FAILED` on someone else's branch (design.md decision 9).
- [ ] 3.3 `config_test.go`: `TestLoadConfigFromEnv_MissingURLReturnsError` (asserts `errors.Is(err, ErrURLRequired)` and a zero `Config`), `TestLoadConfigFromEnv_EmptyURLReturnsError` (set-but-empty is treated as unset, not as a valid URI), and `TestLoadConfigFromEnv_URLIsLoaded`.
- [ ] 3.4 `client_test.go`: `TestOpen_SucceedsAgainstRunningBroker` and `TestOpen_FailsAgainstUnreachableBroker`. The second dials a URI with distinctive userinfo (a username and password that appear nowhere else in the test) and asserts the returned error string contains **neither** — asserting only the password would pass for an error that leaked the username, and the spec forbids exposing the credentials, not just the secret half. Make it an assertion, not a comment: this is task 2.2's real constraint.
- [ ] 3.5 `client_test.go`: `TestPing_SucceedsAgainstLiveConnection`, and `TestPing_FailsAgainstClosedConnection` — the second is the one that would pass against an `IsClosed()`-based implementation too, so pair it with `TestPing_FailsAgainstBrokerClosedFromTheServerSide` if a server-side close can be forced within the test's means; if it cannot, say so in a comment rather than leaving the weaker assertion looking sufficient.
- [ ] 3.6 `client_test.go`: `TestClose_ReleasesConnection` — asserts `Close` returns nil and a subsequent `Ping` on the same connection fails, so the test proves release rather than just a nil return.
- [ ] 3.7 `topology_test.go`: `TestDeclareTopology_IsIdempotent` (call twice with the same test-scoped descriptor, both return nil) and `TestDeclareTopology_DeclaresEveryEntity` (passive-declare each of the four entities and assert each exists). Both drive the exported function; only the names differ from production.
- [ ] 3.8 `topology_test.go`: `TestDeclareTopology_ConflictingRedeclarationIsRejected` — call `DeclareTopology` again with the same names but a different job TTL and assert the broker returns a precondition failure. This is what pins the argument set to something outside this package; without it the descriptor is asserted only against itself. Note that a failed declaration closes the channel, so this test needs its own.
- [ ] 3.9 `topology_test.go`: `TestJobQueueOverflowRejectsAndDeadLetters` — declare a test-scoped topology with `JobMaxLength` 1, publish two messages **on a channel in confirm mode** (`Channel.Confirm(false)`, awaiting each `amqp091.Confirmation`), and assert the second comes back as a negative acknowledgement rather than evicting the first, and that it arrives in the test's dead-letter queue. Confirm mode is not optional here: `basic.publish` is asynchronous and unacknowledged by default, so `PublishWithContext` returns nil whether the broker accepted or refused the message, and a test reading that nil as acceptance would pass against a queue configured with the default `drop-head`. This is the only test that proves `reject-publish-dlx` was applied.
- [ ] 3.10 `topology_test.go`: `TestDeadLetterQueueForwardsNowhere` — assert the dead-letter queue's declared arguments carry a TTL and a max length and no `x-dead-letter-exchange`, since a DLQ that forwards is the unbounded chain task 2.8 exists to terminate.
- [ ] 3.11 `dependency_test.go`: an executable test walking this package's own `.go` files and failing on any import beginning `video-processor/internal/identity/` or `video-processor/internal/video/`. The spec's "imports no bounded context" scenario has no other enforcement — `internal/identity/dependency_rules_test.go` and `internal/video/dependency_rules_test.go` each scan only their own context's `domain`/`application` directories and would not notice an import added here. A prose scenario cannot fail a build.
- [ ] 3.12 `topology_test.go`: `TestDeclareTopology_FailsAgainstClosedConnection`, and `TestDefaultTopology_ReturnsThePinnedValues` — the latter asserting the five names and four bound values literally, since every other topology test runs under test-scoped names and would pass against any defaults at all.

## 4. Local dev & CI infrastructure

- [ ] 4.1 `docker-compose.yml`: add a `rabbitmq` service pinned to `rabbitmq:4-alpine`, matching the major-version pinning `postgres:16-alpine` and `redis:7-alpine` already use and the tag CI will use. Healthcheck `rabbitmq-diagnostics -q ping`; ports published on `127.0.0.1` only, following the `redis` and `minio` services' comment style. Update the file's header comment, which currently says later phases extend it "with RabbitMQ" — that is now this change.
- [ ] 4.2 `docker-compose.yml`: add a named `rabbitmq_data` volume mounted at `/var/lib/rabbitmq`, declare it under top-level `volumes:`, **and pin `hostname: rabbitmq` on the service**. The hostname is not cosmetic and the volume does not work without it: RabbitMQ stores its Mnesia database under `mnesia/rabbit@<hostname>`, and Compose gives a recreated container a fresh generated hostname, so a persisted volume would be reopened by a node with a different name — which starts empty beside the old directory rather than resuming it. Carry that reason in the comment, following `postgres`/`minio` rather than `redis`. Carry design.md decision 8's rationale as a comment, explicitly contrasting it with the `redis` service's deliberate no-volume comment so the difference reads as a decision: Redis holds explicitly non-authoritative data, whereas once the relay has a broker acknowledgement and stamps `published_at`, the message is the only record that the job is still waiting — wiping it loses real work with nothing left in PostgreSQL to replay, the same dangling state `minio_data` exists to prevent. Note in the comment that clearing the relay change's residue therefore needs `docker compose down -v`, not a plain `down`.
- [ ] 4.3 `docker-compose.yml`: add `RABBITMQ_TEST_URL: amqp://guest:guest@rabbitmq:5672/` to the `app-test` service's environment and add `rabbitmq` to `app-test`'s `depends_on` with `condition: service_healthy` — `docker compose run` starts only a service's declared dependencies, so without this the tests in section 3 connect to nothing. Do **not** add a non-test `RABBITMQ_URL` to the `app` service: nothing in `cmd/api` reads it, and adding it would imply a startup requirement this change explicitly does not create.
- [ ] 4.4 `.github/workflows/ci.yml`: add `rabbitmq` to the `test` job's `services:` block — a service container, unlike MinIO. The comment on the MinIO step warns against converting it back to a service container; that warning is specific to an image whose `CMD` lacks its own server arguments. `rabbitmq`'s default command is `rabbitmq-server`, which is exactly what is wanted. Health options mirroring the compose healthcheck (`--health-cmd "rabbitmq-diagnostics -q ping"`), port `5672:5672`.
- [ ] 4.5 `.github/workflows/ci.yml`: add `RABBITMQ_TEST_URL: amqp://guest:guest@localhost:5672/` to the `Test` step's env. `guest` over loopback is the broker's own default account and is fixed, non-secret, and loopback-only here — the same posture as `minioadmin`/`identity`. If `gosec` flags it as a hardcoded credential, annotate narrowly rather than disabling the rule (task 5.5).
