## 2. Package: `internal/platform/rabbitmq`

- [ ] 2.1 `config.go`: `Config` with a single `URL` field, `LoadConfigFromEnv` reading `RABBITMQ_URL`, and an exported `ErrURLRequired` returned when the variable is unset or empty. One field, not a decomposed host/port/user/vhost set — the URI is AMQP's own addressing form and carries the TLS scheme, the credentials, and the vhost that a bare address cannot express. Mirror `internal/platform/redis/config.go`'s shape and error style.
- [ ] 2.2 `client.go`: `Open(cfg Config) (*amqp091.Connection, error)` calling `amqp091.Dial`. Unlike `redis.Open` and `storage.Open` this genuinely connects (design.md decision 2) — record that in a doc comment with the reason, so a later consistency pass does not "fix" it into a deferred-connect shim. The wrapped error must not echo `cfg.URL`: an AMQP URI carries the password in its userinfo component, and this error reaches logs.
- [ ] 2.3 `client.go`: `Ping(conn *amqp091.Connection) error` that opens a channel and closes it. Do **not** use `conn.IsClosed()` — it reports only what this process has already observed, which is stale for exactly the unreachable-broker case a health check exists to catch (design.md decision 3, and the same trap `minio-infrastructure` documents for `minio-go`'s cached `IsOnline`). Note in a comment why the cheap predicate was rejected.
- [ ] 2.4 `client.go`: `Close(conn *amqp091.Connection) error`. Unlike the MinIO adapter, which has no teardown because `*minio.Client` exposes none, an AMQP connection owns a socket and must be released.
- [ ] 2.5 `topology.go`: exported constants for every name and argument — `ExchangeJobs` (`video.jobs`), `RoutingKeyJobQueued` (`video_job.queued`, matching the outbox `event_type` string `add-videojob-source-key-and-outbox-relay` will persist), `QueueJobsV1` (`video.jobs.queued.v1`), `ExchangeDLX` (`video.jobs.dlx`), `QueueDead` (`video.jobs.dead`), plus the TTL and max-length values. The `.v1` suffix is deliberate and not speculative generality: the cutover consumes from a separately named queue rather than purging this one, so the successor is a convention rather than an ad-hoc rename (design.md decision 4).
- [ ] 2.6 `topology.go`: `DeclareTopology(conn *amqp091.Connection) error` opening **its own** channel and closing it before returning, so a failed declaration cannot leave a caller's long-lived channel closed — AMQP gives no way to reopen the same channel. Declaration order is fixed and load-bearing: dead-letter exchange, dead-letter queue, and its binding **first**, then the job exchange, the job queue, and its binding. RabbitMQ does not validate that a queue's `x-dead-letter-exchange` exists at declare time and silently drops dead-lettered messages when it does not, so declaring the sink first makes a partial failure leave an incomplete topology rather than a complete-looking lossy one (design.md decision 6).
- [ ] 2.7 `topology.go`: declare the job queue durable with `x-message-ttl` 1 h, `x-max-length` 10 000, `x-overflow: reject-publish-dlx`, and `x-dead-letter-exchange: video.jobs.dlx`. `reject-publish-dlx` over the default `drop-head`: a refused publish lets the relay leave its outbox row unstamped and retry, while a dropped head is a job that vanishes with no record it was queued — and `reject-publish-dlx` dead-letters what it refuses, so the refusal is inspectable (design.md decision 5).
- [ ] 2.8 `topology.go`: declare the dead-letter queue durable with `x-message-ttl` 24 h, `x-max-length` 10 000, `x-overflow: drop-head`, and **no** `x-dead-letter-exchange`. This is what terminates the chain — a bound on the job queue alone relocates growth into an unbounded sink rather than capping it, and during the window `add-videojob-source-key-and-outbox-relay` opens, that sink is where every message ends up.

## 3. Tests: `internal/platform/rabbitmq`

- [ ] 3.1 Shared helper: read `RABBITMQ_TEST_URL` and `t.Skip` with a clear message naming the variable when unset — matching `internal/platform/redis/client_test.go:21` and `internal/video/infrastructure/storage/client_test.go:30` exactly, not `cmd/api`'s `TestMain` fail-hard posture. Nothing in the running application opens an AMQP connection after this change, so there is no coverage a skip would silently hide.
- [ ] 3.2 Second helper: mint test-scoped topology names derived from the test name plus a random suffix, and register `t.Cleanup` deleting every exchange and queue it declared, so cleanup runs on failure too. Tests must not declare the production constants' names — a test-sized `max-length` left behind under a production name collides with the real declaration later, as `PRECONDITION_FAILED` on someone else's branch (design.md decision 9).
- [ ] 3.3 `config_test.go`: `TestLoadConfigFromEnv_MissingURLReturnsError` (asserts `errors.Is(err, ErrURLRequired)` and a zero `Config`), `TestLoadConfigFromEnv_EmptyURLReturnsError` (set-but-empty is treated as unset, not as a valid URI), and `TestLoadConfigFromEnv_URLIsLoaded`.
- [ ] 3.4 `client_test.go`: `TestOpen_SucceedsAgainstRunningBroker` and `TestOpen_FailsAgainstUnreachableBroker` — the latter also asserting the returned error string contains neither the password nor the full URI (task 2.2's real constraint, so make it an assertion rather than a comment).
- [ ] 3.5 `client_test.go`: `TestPing_SucceedsAgainstLiveConnection`, and `TestPing_FailsAgainstClosedConnection` — the second is the one that would pass against an `IsClosed()`-based implementation too, so pair it with `TestPing_FailsAgainstBrokerClosedFromTheServerSide` if a server-side close can be forced within the test's means; if it cannot, say so in a comment rather than leaving the weaker assertion looking sufficient.
- [ ] 3.6 `client_test.go`: `TestClose_ReleasesConnection` — asserts `Close` returns nil and a subsequent `Ping` on the same connection fails, so the test proves release rather than just a nil return.
- [ ] 3.7 `topology_test.go`: `TestDeclareTopology_IsIdempotent` (call twice, both return nil) and `TestDeclareTopology_DeclaresEveryEntity` (passive-declare each of the four entities and assert each exists).
- [ ] 3.8 `topology_test.go`: `TestDeclareTopology_ConflictingRedeclarationIsRejected` — declare the queue again with a different `x-message-ttl` and assert the broker returns a precondition failure. This is what pins the argument set; without it the constants are asserted only against themselves. Note that a failed declaration closes the channel, so this test needs its own.
- [ ] 3.9 `topology_test.go`: `TestJobQueueOverflowRejectsAndDeadLetters` — declare a test-scoped job queue with `x-max-length` of 1 and the production overflow/DLX arguments, publish two messages, and assert the second is refused rather than evicting the first, and that it arrives in the test's dead-letter queue. This is the only test that proves `reject-publish-dlx` was chosen and applied rather than the default `drop-head`.
- [ ] 3.10 `topology_test.go`: `TestDeadLetterQueueForwardsNowhere` — assert the dead-letter queue's declared arguments carry a TTL and a max length and no `x-dead-letter-exchange`, since a DLQ that forwards is the unbounded chain task 2.8 exists to terminate.
- [ ] 3.11 `topology_test.go`: `TestDeclareTopology_FailsAgainstClosedConnection`.

## 4. Local dev & CI infrastructure

- [ ] 4.1 `docker-compose.yml`: add a `rabbitmq` service pinned to `rabbitmq:4-alpine`, matching the major-version pinning `postgres:16-alpine` and `redis:7-alpine` already use and the tag CI will use. Healthcheck `rabbitmq-diagnostics -q ping`; ports published on `127.0.0.1` only, following the `redis` and `minio` services' comment style. Update the file's header comment, which currently says later phases extend it "with RabbitMQ" — that is now this change.
- [ ] 4.2 `docker-compose.yml`: **no** named volume, following `redis` rather than `postgres`/`minio`. Carry design.md decision 8's rationale as a comment placed against the `redis` no-volume comment it parallels: PostgreSQL is authoritative, a message lost to `docker compose down` is recoverable from an outbox row whose `published_at` was never stamped, and persisting the broker would preserve exactly the stale residue the cutover is designed to make unreachable.
- [ ] 4.3 `docker-compose.yml`: add `RABBITMQ_TEST_URL: amqp://guest:guest@rabbitmq:5672/` to the `app-test` service's environment and add `rabbitmq` to `app-test`'s `depends_on` with `condition: service_healthy` — `docker compose run` starts only a service's declared dependencies, so without this the tests in section 3 connect to nothing. Do **not** add a non-test `RABBITMQ_URL` to the `app` service: nothing in `cmd/api` reads it, and adding it would imply a startup requirement this change explicitly does not create.
- [ ] 4.4 `.github/workflows/ci.yml`: add `rabbitmq` to the `test` job's `services:` block — a service container, unlike MinIO. The comment on the MinIO step warns against converting it back to a service container; that warning is specific to an image whose `CMD` lacks its own server arguments. `rabbitmq`'s default command is `rabbitmq-server`, which is exactly what is wanted. Health options mirroring the compose healthcheck (`--health-cmd "rabbitmq-diagnostics -q ping"`), port `5672:5672`.
- [ ] 4.5 `.github/workflows/ci.yml`: add `RABBITMQ_TEST_URL: amqp://guest:guest@localhost:5672/` to the `Test` step's env. `guest` over loopback is the broker's own default account and is fixed, non-secret, and loopback-only here — the same posture as `minioadmin`/`identity`. If `gosec` flags it as a hardcoded credential, annotate narrowly rather than disabling the rule (task 5.5).
