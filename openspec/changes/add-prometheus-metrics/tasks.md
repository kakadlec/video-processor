## 2. The platform package and its three source rules

- [ ] 2.1 `internal/platform/metrics`: one explicit `prometheus.NewRegistry()` held as process-wide state, a `Handler()` over it via `promhttp.HandlerFor`, and registration of `collectors.NewGoCollector()` and `collectors.NewProcessCollector(collectors.ProcessCollectorOpts{})` into it explicitly. The options value is not optional — at the pinned `client_golang v1.24.1` the signature is `NewProcessCollector(opts ProcessCollectorOpts)` and the zero value selects the defaults, so the argument-free call does not compile; `NewGoCollector` is variadic and takes none. No package in this repository may name `promauto`, `prometheus.DefaultRegisterer`, `DefaultGatherer`, or the package-level `Register`/`MustRegister`.
- [ ] 2.2 The two label constructors, `Route(string) string` and `Method(string) string`, each **total**: every input returns a member of a bounded set, with `<unmatched>` and `UNRECOGNIZED` as the fallbacks. `UNRECOGNIZED` reuses the access record's own spelling (`cmd/video-api/logging.go:63`) deliberately — the same fact should read the same in a record and in a series.
- [ ] 2.3 `BindRoutes`, called once per root at the end of `setupRouter`, taking **this package's own route representation** — a `Method` and a `Path` per entry — and **not** `gin.RoutesInfo`. The conversion from `engine.Routes()` happens in each root. This is not a style preference: no non-test file under `internal/` imports gin today, `internal/platform/logging/dependency_test.go:80-103` states that as a rule about the platform namespace, and 2.4b copies that test into this package — so a `gin.RoutesInfo` parameter here fails this change's own test. Cover the failure mode directly too: with `BindRoutes` never called, `Route` must return `<unmatched>` for everything rather than passing values through — a fail-closed empty table, not an absent one.
- [ ] 2.4 `internal/platform/metrics/disclosure_test.go`, modelled on the logging walk and carrying its two hard-won guards: skip `fs.ErrNotExist` rather than returning `WalkDir`'s error verbatim (the #251 race, still live — the ffmpeg tests create and remove `temp/<jobID>` under their own package directory), and **fail loudly if it parses no file**, so a moved tree cannot report every rule clean while checking nothing.
- [ ] 2.4b `internal/platform/metrics/dependency_test.go`, copied from `internal/platform/logging/dependency_test.go` — all three of its tests: no import outside `internal/platform/`, no bounded-context name in a non-test source, and no import of the HTTP framework. The disclosure walk does not cover any of this; it judges call sites, not placement. The copy is required rather than optional because that test parses `"."` and its own doc comment says a new platform package is unenforced until it carries its own, and the `service-metrics` scenario "A context's family is placed in the shared platform package" has nothing else to be satisfied by. Confirm it actually fails on a `fiapx_video_jobs_…` family declared in this package before moving on.
- [ ] 2.5 Rule 1 — every label value is a string literal or a call to `metrics.Route`/`metrics.Method`, **written as a permission with a failing default rather than as an enumeration of bad forms**. An argument the walk cannot resolve to one of those two fails, including one whose syntactic form it does not recognize. Cover the three positions a label value occupies — `WithLabelValues` arguments, `prometheus.Labels{…}` composite-literal values, `MustNewConstMetric`'s trailing arguments — and make sure the default catches the forms that contain neither a literal nor a constructor anywhere: a **spread** (`WithLabelValues(values...)`), a **converted or variable `Labels`** argument (`With(prometheus.Labels(m))`, `With(labels)`), and a **computed key** inside a `Labels` literal, which is a label *name* chosen at runtime and is not covered by rule 2. Each of those is a one-line bypass of an enumerating walk, which would make "structurally impossible" false as stated.
- [ ] 2.6 Rule 2 — every metric name, help string and label-name list entry is a string literal.
- [ ] 2.7 Rule 3 — the default-registry ban of 2.1, enforced as an import ban on `promauto` **plus** a name ban on the three `prometheus.`-qualified defaults. An import ban alone misses `prometheus.MustRegister(c)`; a name ban alone misses `promauto.NewCounterVec(…)`, which registers into the default registry without naming it.
- [ ] 2.8 Drive the walk over synthetic sources for every form the repository does not contain yet, the way `TestTheWalkJudgesEachFormItMustJudge` does — at minimum: a label value from `strconv.Itoa`, from a `const`, from a variable, from `fmt.Sprintf`; a `prometheus.Labels` composite literal with one literal and one variable value; a `prometheus.Labels` literal with a **computed key**; a **spread** `WithLabelValues(values...)`; a `With(prometheus.Labels(m))` **conversion** and a `With(labels)` **variable**; a `MustNewConstMetric` with a variable label; `promauto` by import; `prometheus.MustRegister`; and the two permitted constructors plus a plain literal, which must pass. The last four synthetic cases are the ones that prove the default fires rather than that the enumeration is long: they contain no literal and no constructor at all, so a walk that only inspects known positions reports them clean.
- [ ] 2.9 See each rule fail before it passes, on the real tree: add a violating call site temporarily, confirm the test names the file and line, remove it.

## 5. The pipeline collector and the two new indexes

- [ ] 5.1 Add **two** partial indexes to `internal/video/infrastructure/postgres/schema.sql`, beside the sweeper's and carrying comments in the same terms: `ON video_jobs (created_at) WHERE status = 'queued'` and `ON video_jobs (created_at) WHERE status = 'processing'`. The second is not redundant with `video_jobs_processing_id_idx`, and the comment should say why: that index is keyed by `id` to match the sweep's keyset cursor, so it finds the processing rows and cannot order them by `created_at` — an oldest-age lookup over it reads every matching row. Confirm the file stays argument-free — pgx forces the simple query protocol for an argument-free `Exec`, and a parameter introduced into this file breaks startup rather than one table.
- [ ] 5.2 The aggregate reads in that package, as methods on the concrete `Repository` and **not** on `domain.VideoJobRepository` (which would oblige the cache decorator and every application-layer fake to carry them, and would make wiring the collector through the cache possible at all): per-state count and oldest `created_at` over `video_jobs` for `queued` and `processing`; per-`event_type` count and oldest `occurred_at` over `video_job_outbox WHERE published_at IS NULL`, restricted to the relayed event types. Restrict the second with the same closed set the relays claim on — an unrestricted version reports the permanent `video_job.created` backlog and climbs forever.
- [ ] 5.3 Write each in-flight state's predicate as a **literal**, one statement or `UNION ALL` branch per state, not `WHERE status = $1`. A partial index with a literal predicate is matched only when the planner can prove the query's predicate implies it, and it cannot prove that for a parameter it does not yet have — so the tidier version silently forfeits both indexes 5.1 just added. Then `EXPLAIN` every statement against a populated database and confirm each is served by its partial index **and that each oldest-age lookup reads a single ordered row**. This is the task that is wrong in a way that looks like a working system: an unindexed aggregate returns the right number and reads the whole table every scrape, forever.
- [ ] 5.4 The count saturates at **10,000** (a bounded subquery) — the number `videojob-persistence` states, used verbatim here and in the collector; the oldest-age lookup does not saturate and must be a one-row index read. Assert the saturation explicitly with more rows than the bound.
- [ ] 5.4b Return an entry for **every** member of each closed label set, with a count of zero and no age where nothing matched — not a bare `GROUP BY`, which omits the row. Absence is how 5.5 reports failure, so an empty `queued` state that reported nothing would be indistinguishable from a database that answered nothing, which is the one distinction this collector exists to make. Cover it: with the queue drained, assert the exposition carries `fiapx_video_jobs_in_state{state="queued"} 0` and carries **no** `fiapx_video_jobs_oldest_in_state_age_seconds{state="queued"}` sample at all.
- [ ] 5.5 **On a query failure, emit no value and report the failure to the scraper** — `prometheus.NewInvalidMetric`, never `0`. Cover it: with the pool closed, assert the gathered output carries no `fiapx_video_jobs_in_state` sample and that the scrape reports an error. A collector that answers `0` under failure is the single most misleading thing this change could ship.
- [ ] 5.6 Bound `Collect` with its own context timeout, and confirm the bound is strictly below whatever scrape timeout is used — the same relationship `service-health-probes` states between a readiness check and its prober, and wrong in the same silent direction.
- [ ] 5.7 Register the collector only in `cmd/video-api`, built on the **undecorated** PostgreSQL repository — the same wiring `GET /download/:filename`'s entitlement lookup already uses, and here a compile-time property rather than a convention, since the decorator does not carry the aggregate methods and cannot be passed where they are required. It reads the video pool; no other process should hold it, and `cmd/worker` holding it would put a query-per-scrape on a process nothing scrapes.
