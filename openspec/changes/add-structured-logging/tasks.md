## 2. The shared package and its enforcement tests

- [ ] 2.1 Create `internal/platform/logging`: JSON handler construction, severity parsing, destination (stdout), and the service/instance identity binding. The instance comes from `os.Hostname()` — the container id under Docker — with a generated fallback when it is unavailable, and is resolved once at construction, never per record. No gin import, no bounded-context import.
- [ ] 2.2 Severity parsing refuses an unparseable value with an error rather than falling back to the default, and the absent case yields informational. Cover both. Provide the bootstrap constructor the refusal is reported through — default severity, same identity fields — so no root needs an unstructured path for it.
- [ ] 2.2a Cover the instance fallback: with `os.Hostname()` unavailable the logger still constructs and still carries a distinct instance value. A field that silently becomes empty is worse than one that is absent, because it reads as "all one instance".
- [ ] 2.3 Copy the placement test `internal/platform/rabbitmq/dependency_test.go` carries into this package. It is per-directory — it parses `.` — so a new platform package is unenforced without its own copy, and this one is exactly where an `internal/video/...` import would be tempting.
- [ ] 2.4 Add the disclosure test: AST-walk every non-test `.go` file under `cmd/` and `internal/`, and fail on any argument a log call passes after its message that is not a call to `slog.String`, `slog.Int`, `slog.Int64`, `slog.Bool`, `slog.Duration` or `slog.Time`. Apply the same requirement to `Logger.With`, whose arguments are **all** attributes and which a message-relative rule does not reach at all — a value bound there rides on every subsequent record rather than one. **Not** `WithGroup`, whose signature is `WithGroup(name string)`: it binds no value, and requiring a typed attribute there would reject every valid call while closing nothing. This rejects `slog.Any`, `slog.Value`, `LogValuer` implementations, and the alternating key-and-value form — but **not** the ordinary `Info`/`Warn`/`Error` functions, which take typed attributes in their variadic. `slog.LogAttrs` is permitted, not required. It fails at this point, which is the point — it goes red before the migration and green after.
- [ ] 2.4a Extend the same walk to hold the other source-level scenario: **no import of the standard `log` package at all**, and no `fmt.Print`/`Printf`/`Println` or `fmt.Fprint*` writing to standard output or standard error. An import ban rather than a list of function names — six of the sites being migrated are method calls on a `*log.Logger` instance, which no enumeration of `log.Print`/`log.Fatal`/`log.Panic` reaches, and a later `log.New` would reintroduce the whole path while such a check stayed green. `fmt.Errorf` and `fmt.Sprintf` produce values and are untouched. One walk, two rules — this is what makes group 4's completion checkable rather than asserted.
- [ ] 2.4c Third rule on the same walk: the message position of every emitting call must be a **string literal**. A `fmt.Sprintf`ed or concatenated message satisfies both attribute rules and the 1.1 call-site count while putting the identifier straight back into the message — the defect the whole change exists to remove, landed by the change itself. Exercise one deliberate dynamic-message violation alongside 2.5's two.
- [ ] 2.4b The walk must skip `ENOENT` rather than returning `WalkDir`'s callback error verbatim. `go test ./...` runs packages in parallel and `internal/video/infrastructure/ffmpeg`'s tests create and delete `temp/<jobID>` under their own package directory, which is inside the tree this walker reads — the exact flake fixed in #251 for the two existing walkers. Make it fail loudly if it parses no file at all, so skipping cannot turn into passing vacuously.
- [ ] 2.5 Verify the disclosure test actually catches the cases it exists for — **three** temporary call sites, not one: a `NotificationPreference` passed to an emitting call, a second bound through `With`, and a third with a `fmt.Sprintf`ed message. Confirm the test names the file and line for each, then remove all three. A source-level test that has never been seen failing is a test of nothing, and the `With` clause is the half that would otherwise ship untried.
- [ ] 2.6a Pin the JSONHandler behaviour the design's decision 2 now rests on, since it was measured rather than assumed and a Go release could change it: a value whose marshalling fails yields a record with an error marker in that attribute and the siblings nested in it lost, the record is still emitted, and logging continues. A test that fails if that stops being true is what keeps the rationale honest.
- [ ] 2.6b Pin the canonical service set in one exported place and assert each root uses it, so the spec's scenarios, the output-shape test and the filters an operator writes cannot drift apart.
- [ ] 2.6 Add a test asserting the JSON handler's output shape for one record — timestamp, level, message, service, instance — so the shape the rest of the change assumes is pinned once rather than in every package.

## 5. The HTTP middleware

- [ ] 5.1 Add `logging.go` to each of `cmd/identity-api`, `cmd/video-api`, `cmd/notification-api`: the gin access-log middleware and the recovery handler. Three copies, deliberately — `cmd/identity-api` is in scope here although it mounts neither auth nor the limiter.
- [ ] 5.2 The access record carries method, matched route, status, duration, size, and the authenticated subject where one exists. It carries no query string, no header, and no body — and no request path for a request that matched a route.
- [ ] 5.2a The path is recorded **only** when no route matched, truncated to a fixed bound. The middleware is global and runs for unmatched requests, where the path is arbitrary caller-supplied text of arbitrary length — the same objection that excludes the query string. Add a test per service for each half: a request with a query string, asserting no part of it reaches the record; and a request to a very long unmatched path, asserting the record is bounded and the record for a *matched* request carries no path at all.
- [ ] 5.3 Replace `gin.Default()` with `gin.New()` plus that middleware and a recovery handler **written here**, in all three roots — not `gin.CustomRecovery`. Verified against the pinned v1.12.0: `CustomRecovery` is `RecoveryWithWriter(DefaultErrorWriter, handle)`, and `CustomRecoveryWithWriter` builds its own `log.Logger` over that writer and prints an ANSI-coloured block to stderr *before* calling the handler — so every recovered panic would emit an unstructured block alongside the record, breaking the one-format requirement.
- [ ] 5.3a Passing `nil` as the writer silences that block but is not the answer either: the broken-pipe branch (`EPIPE`, `ECONNRESET`, `http.ErrAbortHandler`) calls `c.Error` and `c.Abort` and **never reaches the handler**, so that class of panic would be recorded nowhere — a coverage regression against today, where gin at least prints it. Write the middleware directly, keeping gin's branch structure: detect broken pipe the same way, record every recovered panic either way, and preserve each branch's existing response (no body on a dead connection, `500` otherwise).
- [ ] 5.3b Assert both halves: the recovered-panic response is byte-identical to what the service returned before, and **no second, unstructured line reaches stderr** for either branch. The absence is the whole point of not using `CustomRecovery`, so a test that only checks the record would pass with the defect present.
- [ ] 5.4 Set `gin.SetMode(gin.ReleaseMode)` explicitly. Then run the full suite: release mode changes some of gin's own error rendering, and any test asserting on it fails here rather than in production.
- [ ] 5.5 Give each copy its own behavioural tests, which is what the existing auth and rate-limit copies actually carry — they have no cross-copy drift test, and claiming that precedent would be wrong. Each root's tests drive its own middleware through `httptest`, so a copy that drifts fails in its own package.
