## Why

Phase 8 is the last open phase and observability is all that remains in it (`docs/roadmap.md`). This is the first of its three changes, and it goes first because it is the only one that touches every file the other two will.

**The system already logs a great deal, and none of it is machine-readable.** Counted precisely, because the completion check depends on it: **138** package-level `log.Print*` call sites outside tests, **10** `log.Fatal*`, **six** through the one injected `*log.Logger` in `internal/notification/application/deliver_notification.go`, and **four** `fmt.Println` startup banners — **158** emitting sites, across all five composition roots and five `internal/` packages. Every one writes a line of prose to stderr through the standard library's package-level logger. The fields are there — a job id, a lease epoch, a storage key, an attempt number, the `(user, event type, channel)` triple — but they are interpolated into a sentence, so the only way to select on one is a regular expression written against a message that no test pins and any edit may reword.

**The prose has grown a schema anyway, which is the tell.** The call sites carry hand-maintained hierarchical prefixes — `video: worker: sweep: job %s ...`, `notification: notifier: %s job %s: ...`, `video: cache: write ...` — that encode context, process, and subsystem positionally. That is a structured record spelled as a string. It is also unenforced: `cmd/video-api` uses no prefix at all (`download: presign result %s: %v`, `close redis: %v`), so the same field appears under three spellings depending on which file emits it.

**Five processes share one stream and nothing distinguishes them.** `docker-compose.yml` runs identity-api, notification-api, video-api, three worker replicas and the notifier, all logging to their container's stderr with no service name and no instance identity in the payload. Three workers processing three videos at once interleave into one undifferentiated transcript, and `video: worker: job %s completed with %d frames` does not say *which* worker. Correlating an upload to the job that ran it to the notification that announced it means grepping three services for a UUID that is formatted into free text.

**A related defect, found while surveying the call sites and worth fixing in the same pass:** there is no `gin.SetMode` anywhere in the repository and no `GIN_MODE` in `docker-compose.yml` or the `Dockerfile`, so all three HTTP services run gin in **debug mode** in every environment, including the published image. That is not a logging preference — debug mode prints the full route table and a warning banner at startup, and gin's own documentation names it as unsuitable for production.

## What Changes

- **`log/slog` becomes the logging mechanism, with a JSON handler, in all five processes.** Standard library, so **no new dependency**: `docs/operations.md` already sanctions "zerolog or slog", and slog is the one that costs nothing in `go.mod` and nothing in the `govulncheck` surface.
- **All 158 emitting sites become `slog` records** — the 138 package-level `log.Print*` calls, the six that go through the injected `*log.Logger`, and the four `fmt.Println` banners. The hierarchical prefixes stop being string prefixes and become attributes: the positional information they encode is exactly what a structured record is for. The 10 `log.Fatal*` sites become an explicit log-then-exit, because `slog` has no `Fatal` and the exit is a decision the call site should be seen making.
- **Every record carries the emitting service, the individual process instance, and — where one exists — the identifier the record is about.** Two identity fields rather than one, because the second is not derivable from the first: `docker-compose.yml` runs three replicas of `cmd/worker` and they share a service name, so "which worker" is answerable only by an instance field, taken from the container hostname the runtime already assigns. A job id, delivery id or storage key becomes a field that can be selected on rather than a substring of a sentence.
- **A shared, gin-free `internal/platform/logging` package builds the logger; each of the three HTTP roots carries its own thin gin middleware over it.** This follows the split `internal/platform/ratelimit` already established rather than inventing one: no package under `internal/` imports gin today, and this change does not make the first. The three copies are the same deliberate, bounded duplication `package main` forces, and each carries the test that catches it drifting.
- **`gin.Default()` is replaced by `gin.New()` plus that middleware and a recovery handler that logs through `slog`**, and release mode is set explicitly. The access log and the panic log stop being the only two records in the system with a different format from every other.
- **The non-disclosure rules the notification specs already state get a mechanism that survives the change of logger.** `domain.Secret` defends itself through `fmt` — `String`, `GoString`, `Format`, and a `MarshalJSON` that deliberately returns an error. A `slog` JSON handler does not route through `fmt`; it routes through `encoding/json`, and what that costs was measured against Go 1.27 rather than assumed. Two distinct failures, neither of them the one first written here: a **defended** value loses its whole attribute to a `!ERROR:` string — the record survives, but every other field of the struct it was nested in goes with it, so a diagnostic vanishes silently; and an **undefended** value is serialized field by field, verbatim. The second is the leak that matters and it has nothing to do with `Secret`: a value holding a destination URL marshals cleanly and writes its query-string credential into the log. The rule this change adopts is therefore stronger than "redact the secret": **no domain value is passed to a log call at all — only pre-extracted scalars** — and it is pinned at the source level, in the idiom this repository already uses for `TestNoQueryOutsideFindDeliverableSelectsTheSecret` and `TestTheHTTPCompositionRootDoesNotLoadTheSecret`. The rule is also extended to attributes **bound to a logger** rather than passed to one emitting call, which take no message and would otherwise slip past a check phrased around arguments-after-the-message — and would leak into every subsequent record rather than one. What the check does **not** cover is an error's own text: `slog.String("error", err.Error())` satisfies it even when `err` is a `*url.Error`. That half — the `*url.Error` hazard `notification-webhook-delivery` and `notification-email-delivery` specify — stays where it already is, enforced by behavioural tests over the delivery path, which this change leaves in place. The new walk closes the domain-value half only, and this proposal claims no more than that.
- **Log lines and startup banners become English; no response body is touched.** The language policy makes a rewritten string English, and a call site migrated to `slog` is rewritten by definition — including `cmd/video-api/main.go`'s two pt-BR banners. The grandfathered pt-BR JSON `Message`/`error` values in `cmd/video-api/video.go` are **out of scope entirely**: this change moves log output and never a response, so nothing in it touches one. Stated here because CLAUDE.md records that this exact ambiguity produced a review finding on PR #181.
- **One record is added, and the framework's own output is replaced.** Stated precisely rather than as "nothing is added", which would be false in two places. At the application's own call sites nothing is added or removed: each of the 158 changes form and gains fields that were already substrings of its message. The exceptions are deliberate and are exactly two — the accepted-upload record, without which a job's identifier appears in no record from the service that accepted it and the end-to-end check below cannot be made at all; and gin's own output, whose access line is replaced by ours and whose debug banner and route table go away with release mode, which is the point of that half of the change.
- **Explicitly not in scope**: `/health`, `/ready`, the admin listener, `/metrics`, Prometheus, trace or request correlation identifiers, and log shipping or aggregation.

## Capabilities

### New Capabilities
- `structured-logging`: what a log record is in this system — that every process emits machine-readable records on one stream, what every record carries (service and instance identity, level, message, the identifiers the record concerns), that the logger is configured once per composition root and never per package, that no domain value reaches a log call — whether passed to one or bound to a logger — and how that is enforced at the source level, that a job can be followed by its identifier across every process that acts on it, and that the HTTP access log and panic log are records of the same shape as every other.

### Modified Capabilities

None. No existing requirement constrains the log format, so nothing here contradicts one. The several existing requirements that a particular value "SHALL NOT appear in any log line" (`notification-preferences`, `notification-webhook-delivery`, `notification-email-delivery`) are strengthened by the new capability's enforcement rule and are not restated or weakened by it — the new spec cites them rather than duplicating them.

## Impact

- **Changed**: all five composition roots (`cmd/identity-api`, `cmd/video-api`, `cmd/notification-api`, `cmd/worker`, `cmd/notifier`), and the five `internal/` packages that log today — `internal/video/{application,infrastructure/cache,infrastructure/messaging}` and `internal/notification/{application,infrastructure/messaging}`. **New**: `internal/platform/logging`, and one `logging.go` in each of the three HTTP roots.
- **No behaviour changes and no new dependency.** No route, status code, response body, database statement, broker message, or shutdown sequence is altered — the one added record and the replaced framework output are log output, observed by nothing the system does. `go.mod` is untouched.
- **The diff carries Go module inputs, so the full local suite must pass before the change is reported complete** — `docker compose run --build --rm app-test go test ./... -v` is the path that supplies `ffmpeg`, MinIO, and the broker.
- **The unavoidable risk is a test that asserts on log output.** A rewritten message string is invisible to the compiler, and any test matching on one fails at run time rather than at build time. Enumerating those assertions is a first task, not a discovery made while migrating.
- **Accepted cost, named rather than discovered:** `gin.New()` in place of `gin.Default()` means the access log's fields are this repository's choice rather than gin's, and the two are not interchangeable — anything reading the old line format breaks. Nothing in this repository does, and nothing outside it is documented to.
- **A second accepted cost:** the logger is configured per composition root and reached by `internal/` packages through the process-wide default rather than through injection. Injection would touch every constructor in three contexts and every test that builds one, for a change whose subject is the record's shape. `design.md` settles this and states what it costs.
- **`docs/roadmap.md` gains all three Phase 8 rows**, not just this one — this change's marked `archived` with its links, since the rows land in its finalization PR, and the two follow-ups `not-started`. Phase 8's decomposition is the artifact the explore step produced, and `docs/roadmap.md:126` currently says the phase is undecomposed — that line becomes false once, here, rather than three times across three unrelated pull requests.
- **Docs** (finalization PR only): `docs/operations.md`'s Observability section, `docs/architecture.md`, `CLAUDE.md`, and the roadmap rows.
- **Dependencies**: none. It is the first Phase 8 change and depends on no unmerged work.
