## 2. The persistence sentinel

- [ ] 2.1 Add `domain.ErrRepositoryUnavailable` to `internal/video/domain/repository.go`, beside `ErrVideoJobNotFound` and `ErrJobClaimLost`. Its doc comment states what it means and, just as importantly, what it does not: the database could not answer, as opposed to a row that was read and could not be interpreted.
- [ ] 2.2 Wrap driver-level failures in `internal/video/infrastructure/postgres/repository.go` so `errors.Is` reaches the sentinel and the original error stays the wrapped cause. The sites are the `Scan`/`Query`/`Exec` error branches, **not** the `RestoreVideoJob` and value-object parse branches below them in `scanJobRow`. Leave `sql.ErrNoRows` handling exactly as it is.
- [ ] 2.3 Do the wrap across the repository's methods, not only the two the claim step uses. A partial contract is worse than a complete one: a reader cannot tell which errors carry the sentinel without auditing call sites, and the spec states it for the whole repository. **The broadened wrap is licence to *mark*, never to *handle*.** No existing caller's behaviour may change as a result — the sweeper, `CompleteJob`/`FailJob`, and `cache.invalidateAfterAmbiguousWrite` all branch on *whether* there was an error and must keep doing exactly that. The test for this half is that the existing suite passes unchanged; if a test had to be adjusted for anything other than the new sentinel's presence, something was handled that should only have been marked.
- [ ] 2.4 Add the pass-through assertion for `CachedVideoJobRepository` as a test even if no code change is needed. An inherited property that nothing pins is one refactor from being lost.
- [ ] 2.5 Cover the three discriminations as tests against a real database: unreachable carries the sentinel; a row that will not reconstruct does **not**; an unknown id returns `ErrVideoJobNotFound` and does **not**. The second is the one that is easy to skip and is the reason the sentinel is narrow — construct it by writing a row with a status outside the closed set directly through SQL.

## 5. The handler

- [ ] 5.1 Add one case to `handle`'s switch for `errors.Is(err, videodomain.ErrJobClaimUndecided)`, returning `videomessaging.Requeue`. Place it among the other sentinel cases, before `case err != nil`. The default branch keeps its text and its behaviour untouched.
- [ ] 5.2 Rewrite `handle`'s doc comment (`cmd/worker/main.go:368-376`). "Requeueing is never right" is now false as written and was the sentence that made the defect invisible. Replace it with the rule: the disposition turns on whether this worker's claim was **decided**, dead-letter is the default for everything else, and one positively-identified condition retries. Say why the default stays rejection — an unanticipated failure must behave as it does today rather than enter a loop nobody reasoned about.
- [ ] 5.3 Log the requeue at warn with the existing field vocabulary — `component`, `job_id`, `error` — and a string-literal message. Match `cmd/notifier`'s wording where it fits; the two consumers now do the same thing and should read that way.

- [ ] 5.5 Cover the disposition table as a whole, in both directions. A dispatch whose claim could not reach the database **requeues**; a lost claim, an unknown job, an undecodable body, a missing source key, a fenced write, and a post-claim terminal-write failure all still **dead-letter**. The negative half is the decision; a test asserting only the new case passes with the default branch broken.
- [ ] 5.6 Assert the no-side-effects half explicitly for the requeue path: the job is still `queued`, no lease was acquired, no source object was read, no idempotency key was cleared, and nothing reached the dead-letter queue. That set of facts is what licenses the disposition, and a test that checks only the disposition does not check the licence.
