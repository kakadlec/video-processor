## 2. The persistence sentinel

- [ ] 2.1 Add `domain.ErrRepositoryUnavailable` to `internal/video/domain/repository.go`, beside `ErrVideoJobNotFound` and `ErrJobClaimLost`. Its doc comment states what it means and, just as importantly, the two things it does **not** mean: it is not *the database answered and refused*, and it is **not a promise that the statement had no effect** — a connection lost in flight leaves the outcome unknown, and every caller of this sentinel is written against that weaker guarantee.
- [ ] 2.2 Implement the classification as a **permission list over the error's own evidence**, in one unexported helper in `internal/video/infrastructure/postgres`, and mark only what that helper admits. **Do not classify by which driver method returned the error.** Marking whatever `Scan`, `Query` or `Exec` returned is a call-site rule, not an availability one, and it is the defect this task exists to avoid: `row.Scan` returns a lost connection and a permanent `database/sql` conversion or destination-count failure through the same value (`sql: expected N destination arguments in Scan, not M` is what the `SELECT`/`Scan` transposition `scanJobRow`'s comment warns about produces, on every row, forever), and `Query`/`Exec` return a lost connection and a server-answered refusal alike (`42P01` undefined table, `42703` undefined column, `42501` insufficient privilege, `23505` unique violation — the first two being what a half-applied migration produces, which under a call-site rule would mark *every* call unavailable and spin all three replicas). Mark only the evidence task 1.7 confirmed; anything else stays unmarked and keeps dead-lettering. Wrap so `errors.Is` reaches `domain.ErrRepositoryUnavailable` with the original preserved as the cause, and leave `sql.ErrNoRows` handling exactly as it is. The `RestoreVideoJob` and value-object parse branches below the `Scan` stay unmarked as before.
- [ ] 2.3 Apply the classifier across the repository's methods, not only the two the claim step uses. A partial contract is worse than a complete one: a reader cannot tell which errors carry the sentinel without auditing call sites, and the spec states it for the whole repository. **The broadened marking is licence to *mark*, never to *handle*.** No existing caller's behaviour may change as a result — the sweeper, `CompleteJob`/`FailJob`, and `cache.invalidateAfterAmbiguousWrite` all branch on *whether* there was an error and must keep doing exactly that. The test for this half is that the existing suite passes unchanged; if a test had to be adjusted for anything other than the new sentinel's presence, something was handled that should only have been marked.
- [ ] 2.4 Add the pass-through assertion for `CachedVideoJobRepository` as a test even if no code change is needed. An inherited property that nothing pins is one refactor from being lost.
- [ ] 2.5 Cover **four** discriminations, not three, because the fourth is the one the review turned on.
  - **(a) An unreachable database carries the sentinel.** Point the DSN at a closed port, or stop the container.
  - **(b) A server-answered permanent error does *not*.** `ALTER TABLE video_jobs DROP COLUMN content_hash` in the test database, then `FindByID`, which yields `*pgconn.PgError` `42703 undefined_column`. This is the test that kills the call-site rule outright: under it, a half-applied migration would mark every call unavailable and spin every replica forever. **Run it against its own throwaway database, created and dropped by the test** — not against the shared one with a restore afterwards. A DDL change to a table every other test in this package reads would fail them all if the restore did not run or if anything else touched the pool meanwhile, and an implementer reading task 2.3 would then conclude the broadened marking had handled something it should only have marked.
  - **(c) A row that will not reconstruct does *not*.** Write a row with a status outside the closed set directly through SQL.
  - **(d) An unknown id returns `ErrVideoJobNotFound` and does *not*.**
  Add the row-interpretation half of (b) at whatever seam is cheapest — a `rowScanner` stub returning a `database/sql` conversion error is enough, and needs no DDL — since it is the other half of what (b) proves and the two together are what the spec's "never by which method returned it" rule means in practice.

## 3. The unknown-claim-outcome sentinel

- [ ] 3.1 Add `domain.ErrJobClaimOutcomeUnknown`, a sibling to `ErrJobClaimLost`, with a doc comment stating the contrast in one line: lost means another actor owns this job, unknown means this call cannot say who owns it — including whether this worker does. Name it for the *outcome*, not for the claim: "undecided" asserts the transition did not happen, which a single autocommit statement whose result is read over the same connection cannot guarantee, and that false implication is what the review on this proposal found.
- [ ] 3.2 In `internal/video/application/process_video_job.go`, at the single site where `Execute` propagates `uc.start.Execute`'s error, convert an error carrying `ErrRepositoryUnavailable` into `ErrJobClaimOutcomeUnknown` wrapping the original, so both remain reachable by `errors.Is`. Nothing else on that path changes: no `FailJob`, no download, no lease, no cleanup — and **no follow-up read to resolve the ambiguity**, which the spec forbids and which would answer a question the disposition does not ask.
- [ ] 3.3 **Do not apply the conversion anywhere else**, and add the test that pins it: a `FailJob` write that cannot reach the database must return an error that does *not* carry `ErrJobClaimOutcomeUnknown`, so the worker keeps dead-lettering it and the sweeper keeps owning that `processing` row. Without this test the natural refactor — marking the condition once at the repository and branching wherever it appears — passes everything else.
- [ ] 3.4 Leave `StartProcessing` itself unchanged. It propagates the repository's error, which now carries the marker; adding a second conversion there would put the same decision in two places.

## 5. The handler

- [ ] 5.1 Add one case to `handle`'s switch for `errors.Is(err, videodomain.ErrJobClaimOutcomeUnknown)`, returning `videomessaging.Requeue`. Place it among the other sentinel cases, before `case err != nil`. The default branch keeps its text and its behaviour untouched.
- [ ] 5.2 Rewrite `handle`'s doc comment (`cmd/worker/main.go:368-376`). "Requeueing is never right" is now false as written and was the sentence that made the defect invisible. Replace it with the rule: the disposition turns on whether this worker **learned its claim's outcome**, dead-letter is the default for everything else, and one positively-identified condition retries. Do not write "the claim was decided" — the requeue path covers a claim that may well have been decided in this worker's favour without its ever finding out. Say why the default stays rejection — an unanticipated failure must behave as it does today rather than enter a loop nobody reasoned about.
- [ ] 5.3 Log the requeue at warn with the existing field vocabulary — `component`, `job_id`, `error` — and a string-literal message. Match `cmd/notifier`'s wording where it fits; the two consumers now do the same thing and should read that way.
- [ ] 5.4 Pass `videomessaging.DefaultRequeuePause` at the `NewConsumer` call site (`cmd/worker/main.go:147`), and thread it through `run`'s parameters only if a test needs to shorten it — follow whatever `drain` and `sweep` already do rather than inventing a second convention.
- [ ] 5.5 Cover the disposition table as a whole, in both directions. A dispatch whose claim outcome the repository could not report **requeues**; a lost claim, an unknown job, an undecodable body, a missing source key, a fenced write, a post-claim terminal-write failure, **and a claim step that failed with an error the database itself answered** all still **dead-letter**. The negative half is the decision; a test asserting only the new case passes with the default branch broken, and the last entry is the one that distinguishes this change from the call-site rule it rejected.
- [ ] 5.6 Assert the licence, not just the disposition — and do it in **both** branches the sentinel admits. This is two tests, not one, and the second is the one the review asked for.
  - **A definite pre-statement outage.** With the claim statement unable to reach the server at all, assert the message is requeued **and** that the job is still `queued`, no lease was acquired, no source object was read, no idempotency key was cleared, and nothing reached the dead-letter queue.
  - **An ambiguous commit.** This cannot be built against a real database — the socket cannot reliably be dropped between `COMMIT` and the result read — so build it at the repository seam: a stub or decorator whose `ClaimForProcessing` performs the `queued → processing` transition and *then* returns an error carrying `ErrRepositoryUnavailable`. Assert that the handler requeues on the same sentinel, that the redelivery is refused by the claim and **dead-lettered**, and that the row is left `processing` with no lease — then drive a sweep and assert it recovers the row on the ordinary two-observation path. **Do not assert the row is unchanged here**; it is not, and that assertion is the one a reader will otherwise copy across from the first test.
