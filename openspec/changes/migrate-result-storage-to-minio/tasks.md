## 1. Domain: the port, the sentinel, and key derivation

- [ ] 1.1 `internal/video/domain/result_storage.go`: define the `ResultStorage` port with `Put(ctx, key StorageKey, localPath string) error`, `Open(ctx, key StorageKey) (io.ReadCloser, int64, error)`, and `Stat(ctx, key StorageKey) (int64, time.Time, error)`, plus `ErrResultNotFound`. Document on `Open` that the size is returned so an HTTP caller can set `Content-Length` without a second round trip, and that implementations must resolve existence before returning (design.md decision 6) — a lazily-failing reader would surface its error after the response had already begun.
- [ ] 1.2 `internal/video/domain/storage_key.go`: add `ResultStorageKey(jobID VideoJobID) StorageKey` producing `frames_<jobID>.zip`, and `VideoJobIDFromStorageKey(key StorageKey, parser VideoJobIDParser) (VideoJobID, error)` for the inverse. Both live in the domain rather than the adapter because the write and read sides must agree on one convention (design.md decision 3). Carry a comment recording the hard constraint from design.md decision 2: **the key must contain no `/`**, because `app.js` uses it verbatim as `GET /download/:filename`'s single path segment and a `%2F` would break the route match. Someone will eventually try to "organize" the bucket with prefixes; the comment is what stops that from silently breaking the frontend.
- [ ] 1.3 `internal/video/domain/frame_extractor.go`: change `ExtractFrames`'s first return value from `StorageKey` to `zipPath string`. Update the port's doc comment — the extractor produces a local zip and no longer knows where it ends up.

## 2. Storage adapter

- [ ] 2.1 `internal/video/infrastructure/storage/result_storage.go`: `ResultStorage` struct holding a `*minio.Client` and the bucket name, a `New…` constructor, and `var _ domain.ResultStorage = (*ResultStorage)(nil)`.
- [ ] 2.2 `Put`: `client.FPutObject(ctx, bucket, key.String(), localPath, minio.PutObjectOptions{ContentType: "application/zip"})`. `FPutObject` (not `PutObject`) so the content length comes from the file rather than from buffering an unsized reader.
- [ ] 2.3 `Open`: `client.GetObject`, then call the returned object's `Stat()` **before returning anything to the caller** — that is what resolves existence eagerly and yields the size. Map a `NoSuchKey` response code to `ErrResultNotFound`; wrap everything else. Close the object on any error path so a failed open leaks no connection.
- [ ] 2.4 `Stat`: `client.StatObject`, returning `ObjectInfo.Size` and `ObjectInfo.LastModified`, with the same `NoSuchKey` → `ErrResultNotFound` mapping.
- [ ] 2.5 Verify empirically, against the pinned `minio/minio:RELEASE.2025-04-22T22-12-26Z` and `minio-go v7.3.0`, whether `GetObject` itself reports a missing key or whether the error only surfaces from `Stat()`/`Read`. Design.md decision 6 is written to be correct either way, but the finding must be recorded in a comment rather than left as an assumption — this repo has already shipped three review findings that were specification text contradicting verifiable library behavior.
- [ ] 2.6 Add the missing assertion for `minio-infrastructure`'s "Endpoint validation is the client library's, not this adapter's" scenario: `client_test.go` currently records in a comment only that `Open` tolerates a scheme-prefixed `http://host:port`. Turn it into a real assertion. This closes the gap flagged during PR #176's review.

Write the zip to `temp/<jobID>.zip` and return that path. `createZipFile`'s path-confinement check moves from `outputs/` to `temp/`. Keep the per-job frame directory and its `defer os.RemoveAll` exactly as they are — that scenario stays true and must not be disturbed.
- [ ] 3.2 `internal/video/application/process_video_job.go`: add a `domain.ResultStorage` dependency. After a successful extraction, derive the key, `Put` the zip, and `defer os.Remove(zipPath)` so the local copy goes whether the upload succeeds or fails. That work no longer exists — the honest justification is that `CompleteJob` remains the caller's call so `handleVideoUpload` keeps a single place to decide the job's terminal state. Do not leave the stale sentence standing.
- [ ] 3.4 `internal/video/application/fakes_test.go`: add a fake `ResultStorage` (in-memory map, plus injectable failure) for the use-case tests.

## 4. Repository and listing use case

- [ ] 4.1 `internal/video/domain/repository.go`: add `FindCompletedByUserID(ctx, userID UserID, offset, limit int) ([]*VideoJob, error)` to `VideoJobRepository`, documented as ordering identically to `FindByUserID`.
- [ ] 4.2 `internal/video/infrastructure/postgres/repository.go`: implement it. The `status = 'completed'` predicate goes **in the `WHERE` clause**, so `LIMIT`/`OFFSET` apply to completed rows only. Filtering after pagination would let a run of recent `pending`/`failed` jobs push a user's completed results out of the page entirely (design.md decision 5).
- [ ] 4.3 `internal/video/infrastructure/cache/repository.go`: pass `FindCompletedByUserID` straight through, uncached, exactly as `FindByUserID` already is — the cache is keyed per job ID and has nothing to offer a listing.
- [ ] 4.4 `internal/video/application/list_user_results.go`: new `ListUserResults` use case over the repository and `ResultStorage`. For each completed job, `Stat` its object and emit `{StorageKey, Size, ModifiedAt}`. A `Stat` failure — missing object or storage error — **omits** that entry and continues; it must not fail the request. This mirrors what `handleStatus` does today when `os.Stat` fails on a file.
- [ ] 4.5 Update every in-memory/fake repository in the test files to satisfy the widened port (`cmd/api/video_test.go`'s `inMemoryVideoJobRepository`, and any fake in `internal/video/application`).
