- [x] 1.1 Add `github.com/minio/minio-go/v7` to `go.mod`/`go.sum`, pinned to the verified version: `go get github.com/minio/minio-go/v7@v7.3.0`, then `go mod tidy`. The pin is deliberate — design.md decisions 4 and 7 rest on behavior checked against exactly v7.3.0 (`minio.New`'s failure modes, `credentials.NewStaticV4`'s lack of validation, the absence of any `Close`). Taking whatever v7 release is latest at implementation time could invalidate those decisions silently. ## 2. `internal/video/infrastructure/storage` package

- [x] 2.1 `config.go`: `Config` struct (`Endpoint`, `AccessKey`, `SecretKey`, `Bucket string`, `UseSSL bool`), a sentinel error per missing required variable (following `internal/video/infrastructure/postgres/config.go`'s `ErrDSNRequired` style, including its `video:` error prefix), and `LoadConfigFromEnv()` reading `VIDEO_MINIO_ENDPOINT`, `VIDEO_MINIO_ACCESS_KEY`, `VIDEO_MINIO_SECRET_KEY`, `VIDEO_MINIO_BUCKET`, and the optional `VIDEO_MINIO_USE_SSL`.
- [x] 2.1a `config.go`: parse `VIDEO_MINIO_USE_SSL` with `strconv.ParseBool` — unset/empty falls back to `false`, but a **non-empty unparseable value returns an error**, never a silent `false`. A bare `raw == "true"` comparison would turn a deployment typo (`ture`, `yes`, `TRUE ` with trailing space) into a plaintext connection to an endpoint the operator believed was TLS-protected. This mirrors `internal/platform/ratelimit/config.go`'s `positiveIntFromEnv`, which already treats "absent" and "present but invalid" as different outcomes.
- [x] 2.2 `client.go`: `Open(cfg Config) (*minio.Client, error)` — constructs the client via `minio.New(cfg.Endpoint, &minio.Options{Creds: credentials.NewStaticV4(...), Secure: cfg.UseSSL})`, no connectivity check, error propagated with a package-prefixed `fmt.Errorf` wrap (matching `postgres.Open`'s wrapping style). See design.md decision 4 for why this returns an `error` where `redis.Open` does not — endpoint/transport construction, **not** credential validation, which `credentials.NewStaticV4` does not perform.
- [x] 2.3 `client.go`: `Ping(ctx context.Context, client *minio.Client, bucket string) error` — issues a real round trip via `client.BucketExists(ctx, bucket)`, wraps a failure. Do **not** use `minio-go`'s `IsOnline()` (design.md decision 5: it reports a cached background observation and ignores the caller's context).
- [x] 2.4 `client.go`: `EnsureBucket(ctx context.Context, client *minio.Client, bucket string) error` — `BucketExists`, then `MakeBucket` only if absent; treat **only** `BucketAlreadyOwnedByYou` as success (via `minio.ToErrorResponse(err).Code`), propagating everything else. This task originally also listed `BucketAlreadyExists` as benign; that was corrected during PR #174's review — it means the name is owned by a different account, so the bucket is unusable and the error must surface (see design.md decision 6). No policy/versioning/lifecycle configuration.
- [x] 2.5 Do **not** add a `Close`/teardown function — `*minio.Client` (v7.3.0) exposes none and keeps its transport unexported, so a wrapper could only return `nil` while releasing nothing (design.md decision 7). Record the absence in the package doc comment so the asymmetry with `internal/platform/redis` and with `postgres`'s `*sql.DB` reads as intentional.
- [x] 2.6 Package doc comment: state that this package holds the Video Processing context's MinIO connection plumbing and will hold its `StoragePort` adapter (added by `migrate-result-storage-to-minio`), mirroring how `internal/video/infrastructure/postgres` holds `config.go`/`db.go` beside `repository.go`.
